# Vault：Qwen3.5 + SWE-Agent LoRA 原型实施计划

> 本文件供后续按任务逐步实施和审核；当前仅完成上游代码阅读及计划，未固定可运行 SWE-Agent 版本、未转换/合并训练数据、未跑真实数据训练或仓库基线。

**目标：** 固定一套实际可运行的 SWE-Agent 工具配置，从现有 200 条 SWE-smith 训练候选中筛出信息完整的短样本，对 Qwen3.5-0.8B 做一轮 QLoRA，并在相同受控小仓库任务上比较微调前后。

**架构：** 保留现有 ADP 和原始数据作为只读输入；参照 ADP 官方 `sweagent` 转换器，将轨迹映射成 SWE-Agent 的系统提示、XML 风格动作和观测；优先评估用 LLaMA-Factory 读取上游对话并完成 Qwen3.5 的模板、token 化与标签处理；仅在版本或本机显存不兼容时再考虑使用本地训练脚本。离线微调用训练框架执行；运行时 SWE-Agent 通过本地模型接口执行工具循环。框架与模型微调是不同进程/职责。

**技术：** 本机 Qwen3.5-0.8B 固定 revision `2fc06364715b967f1860aea9cf38778875588b17`；4-bit NF4 + PEFT LoRA；SWE-Agent、容器、工具配置和模型服务版本将在任务 1 验证后固定。模型使用 4 GiB 显存的适配仍需真实数据实测。

**上位计划与现有记录：** [总体计划](../../vault-personal-agent-development-plan.zh-CN.md)、[本机 LoRA 测试](../../vault-qwen35-lora-training-test.zh-CN.md)、[原始工具核查](../../vault-stage1-tool-interface-review.zh-CN.md)。

## 一、转换格式：以论文仓库为首要参考

### 1.1 实际已阅读的上游代码

官方仓库 [neulab/agent-data-protocol](https://github.com/neulab/agent-data-protocol)，本次核查固定提交 `ab1180306a3d4d27e9195448c90f030607eba981`（2026-03-02；论文 v2 发表在其后，不等同已核实训练时运行的精确代码）：

- [agents/sweagent/std_to_sft.py](https://github.com/neulab/agent-data-protocol/blob/ab1180306a3d4d27e9195448c90f030607eba981/agents/sweagent/std_to_sft.py)：ADP → SWE-Agent 对话。
- [agents/sweagent/system_message.py](https://github.com/neulab/agent-data-protocol/blob/ab1180306a3d4d27e9195448c90f030607eba981/agents/sweagent/system_message.py)：`bash`、`str_replace_editor`、`submit` 说明和输出约定。
- [agents/sweagent/api.py](https://github.com/neulab/agent-data-protocol/blob/ab1180306a3d4d27e9195448c90f030607eba981/agents/sweagent/api.py)：读取数据源的 API 声明和签名。
- [SWE-smith → SWE-Agent 样本](https://github.com/neulab/agent-data-protocol/blob/ab1180306a3d4d27e9195448c90f030607eba981/datasets/swe-smith/sample_sft/sample_sft_sweagent.json)：上游示例。

这版转换器输出包含 `id`、`system`、`conversations`；对话含 `from: human/gpt` 和 `value`。它把 Bash 代码动作封装为 `<function=bash>` 和 `<parameter=command>` 等文本；API 动作根据签名处理；环境反馈带 `OBSERVATION:`；终止可映射为 `submit`。它可保留已有的描述/推理内容，但不需要捏造缺失思维链。它输出的是训练框架可读取的对话数据，没有在该转换脚本中预先生成 `input_ids` 或 loss mask。论文使用 LLaMA-Factory 执行 SFT；这类步骤可由训练框架在读取数据时完成，并不要求我们手写。我们仍需确认选定 LLaMA-Factory 版本支持 Qwen3.5、适配该数据字段、模板、标签和本机环境；若验证失败，再考虑基于已有脚本实现必要处理。

上游 README 声明项目 MIT，数据可能有单独许可；历史提交根目录未发现独立 LICENSE 文件。直接调用/改写前核对适用许可并保留来源、版本和必要声明。既有转换结果并非针对本任务验证过的可执行实现。

### 1.2 参考而不盲目照搬

1. 首先建立隔离的上游对照环境，在该固定提交上运行官方转换器和官方样本，保存环境、输出和错误；验证现有 `paper_adp_v2` 是否能满足上游 Pydantic schema 和所需字段，不预设可直接导入。
2. 实施时优先直接调用官方转换逻辑或做薄适配；若依赖/格式/目标运行版本不能满足，再以其行为和样例为基准实现必要适配，逐项比对差异，记录代码来源。目标运行接口必须以**实际固定版本的解析器和工具实现**为准，而非只因 XML 文本相似就宣称兼容。
3. 安全性与语义限制：上游 `api.py` 对 `available_tools` 有 `exec(...)` 路径，不能对不可信数据执行；本轮 SWE-smith 仅使用固定、经核验的三个工具声明。上游还会将某些数据集 API 包装成 Bash、将 Python 代码拼接为 shell 字符串、过滤部分网页标识；这些不能默认与真实工具等价，也不得把未经验证的工具映射或 shell 引号当作安全可靠。无法验证则暂缓并记录。
4. 上游 `get_system_message` 的具体行为、数据集专有说明插入位置、`OBSERVATION` 前缀和动作顺序均须实际对照；不声称当前提议的训练模板已验证合理。记录 LLaMA-Factory 实际使用的 Qwen3.5 模板、mask 和长度设置；如果采用不同训练器或更改处理方式，也记录差异。
5. 固定上游和目标 SWE-Agent 版本、系统提示 hash、动作解析器、工具定义、tokenizer、样本转换代码版本和随机种子；从历史输入到模型生成的文本做解析器往返测试。仓库当前主线可能已变化，避免把不同版本混为论文复现。

### 1.3 提前发现的显存/长度关口

用已缓存的 Qwen3.5 tokenizer 实测，上游 `base_template` 为 **3,912 字符、945 token**（不含聊天模板、用户任务、观测和目标）。这比此前本机 512 token 补齐合成短测更长；若采用 512 token 截断，可能丢失部分工具定义或任务，需要记录截断结果。

本轮目标是跑通原型。先统计长度并从短样本开始；超过实测可用上限时，**允许按固定规则截断**，不以保留完整轨迹作为训练的必要前提。优先复用选定 LLaMA-Factory 版本的截断能力；固定最大长度、截断方向及其实际规则，以小样例验证并记录。尽量保留当前助手训练目标和相关工具提示，但无需为每条截断样本补齐全部上下文；标签必须有有效的助手目标 token。记录每条截断前后长度、被截断位置和样本数量，保留未截断 ADP，便于以后大 GPU 重新处理。训练和评测必须明确各自使用的截断与上下文规则；不能将本轮结果称为完整上下文的论文复现。仍有 OOM 时进一步缩短长度或减少批量。

## 二、已有数据、划分与验收边界

当前输入路径 `.memo-vault/agent-training/datasets/paper_adp_v2/`：

| SWE-smith 子集 | 轨迹数 | 后续用途 |
|---|---:|---|
| `train/general` | 100 | 加入训练候选清单 |
| `train/domain` | 100 | 加入训练候选清单 |
| `validation/validation` | 20 | 验证候选，只用于调参和方案选择 |
| `test/test` | 20 | 保留为最终测试候选 |

这 200 条都是训练**轨迹候选**，不等于 200 条可训练样本。一条轨迹可能包含多个决策。已检查 4 个集合的轨迹 ID 和仓库 group 两两不交；仍需检验原始来源哈希、任务近重复、源环境工具定义以及跨数据源泄漏。SWE-smith 任务基于合成缺陷，轨迹是记录的 agent 交互；不等同真实 SWE-Bench Verified。原数据、ADP 及旧报告均只读，不覆盖；创建新 manifest 和版本化输出。

当前优先只用 SWE-smith；AgentInstruct/CodeAct 的训练候选可后续审计再决定是否混入。网页数据不作为本轮默认输入。上游轨迹验证集是**离线预测验证候选**，不保证可以在本机重建原仓库状态；真实闭环另设独立的小仓库任务，不能把离线观测当真实执行。

## 四、分步实施和验收

### 任务 1：固定真实 SWE-Agent 工具配置

- [ ] 在隔离目录安装/固定 SWE-Agent commit、依赖、工具包配置、解析器及提示；核实其许可证与官方接口，保存版本和 hash。
- [ ] 检查 Docker 命令、daemon、容器镜像、可用磁盘/内存，确认仓库沙箱实际可运行；工具仅作用于临时仓库，控制网络、步骤及超时。
- [ ] 选择与上游 XML 动作及 `bash`、`str_replace_editor`、`submit` 兼容的一套具体配置；若当前版本差异较大，记录映射/选取可运行版本，不擅自声称与历史版本一致。
- [ ] 在不接 Qwen 时用固定动作验证解析、调用、观察、错误和正常终止；保留最小可复现实验。
- [ ] 检查模型接口连接方案，验证 Qwen3.5 推理是否支持该框架需要的消息格式、提示模板、模型输出解析及思考开关。Qwen3.5 非思考/思考行为需固定；不能假定 OpenAI 原生 tool_calls 与 XML 文本可互换。

**验收：** 真实框架在临时仓库能解析一次规定动作、执行并返回可追溯结果；记录准确 commit、配置和运行方式。若环境不可用，输出阻塞项，不用 mock 冒充真实框架。

### 任务 2：整理并校验 200 条训练候选

- [ ] 读取 `train/general/swe_smith.jsonl` 和 `train/domain/swe_smith.jsonl`，生成只指向来源的训练 manifest；保留原分组、原划分和文件哈希，不改写源数据。
- [ ] 单独生成验证 20 条及测试 20 条 manifest；统计 trajectory ID、source row、仓库组、task hash 的跨划分冲突，必要时检查近重复；出现泄漏则隔离并说明。
- [ ] 对合并的两个训练子集以及验证/测试各自执行源文件哈希、轨迹重建、工具链接及结果/终止检查。已有 general 审计不等于 domain 已完成。
- [ ] 输出原始数量、候选、排除/待核实原因；记录每个源记录是否 `resolved`，保留失败/错误反馈的真实语义，区分真实调用与合成任务来源。

**验收：** 训练清单原始应有 200 条轨迹，验证/测试各 20 条；审核后的有效数量以实际报告为准。拆分、来源和原因可追溯；不合并验证/测试。

### 任务 3：对照上游并筛选短样本

- [ ] 获取固定上游提交、运行官方样例；核验依赖、Schema、SWE-smith API 和本项目 ADP 的字段差异。
- [ ] 在本机候选上运行或安全适配上游转换；记录每条失败和原因，保留调用 ID、结果、参数和原轨迹索引。对上游输出和适配输出作逐事件比对，跑所选 SWE-Agent 解析器测试。
- [ ] 基于固定工具配置构造系统说明和会话；测量真实 Qwen3.5 tokenizer 全模板长度 p50/p90/max，以及当前完整提示 945 token 所带来的影响。
- [ ] 按单个助手决策生成研究候选，分组继承所属轨迹；同一轨迹的样本绝不跨训练/验证/测试。超长样本允许截断，记录截断的内容与长度；参数缺失或工具版本不明按映射结果记录。
- [ ] 先选少量代表性的真实训练样本（覆盖 Bash、文件读取/编辑、工具结果、结束动作；失败和长样本另行审阅）；人工查看转换前后，确认无提示/标注泄漏。数量以合法样本为准，不凑数。
- [ ] 目标 mask：模板、system、user、环境反馈、历史一律不计算 loss；每个样本只对当前助手动作及所需结束标记计算 loss。验证 Qwen3.5 thinking / 非 thinking 格式与框架实际解析一致，前缀不匹配时记录暂缓；不生成虚构的推理或反馈。

**验收：** 至少一条真实来源轨迹可通过源→ADP→上游/适配→目标解析的语义检查，且最终训练样本有固定 tokenizer、来源与 labels；数量不满足时报告具体缺口。若 945 token 的工具提示使 4 GiB 无法支撑，按 1.3 使用记录清楚的截断方案完成原型，并明确上下文可能不完整。

### 任务 4：原始 Qwen 的固定小仓库基线

- [ ] 设计不少于几个人工可核查的轻量任务（数量以实际可复现为准）：每个任务有独立初始仓库/commit、明确问题、评测脚本和预期状态。训练任务、验证任务和最终测试任务分组隔离；不可把其中评测答案泄漏给训练模型。
- [ ] 编写固定运行配置，所有测试仓库从相同快照创建；限制执行范围、步数、超时与网络，记录实际工具调用、状态、日志和运行时间。
- [ ] 将无 Adapter 的 Qwen3.5 加载到本机服务并接入真实 SWE-Agent，验证生成文本由实际解析器处理、工具执行和结果返回。固定采样、随机种子/不确定性、thinking 设置，测量可用上下文预算和推理显存。
- [ ] 记录解析成功率、工具名/参数合法率、完成率、执行步骤数、失败案例及每项分母；保存仓库复位与工具配置证据。

**验收：** 至少完成从用户任务→模型→真实框架工具→结果的可重复闭环，即便原始模型无法解题也记录基线；不得将手工编造工具结果视作基线闭环。验证任务用于调参，保留独立最终测试任务。

### 任务 5：真实轨迹 LoRA 短训练

- [ ] 优先验证 LLaMA-Factory 对本机 Qwen3.5、SWE-Agent 对话数据、QLoRA 和 CUDA 的支持；核对 dataset_info、模板、角色、mask、截断参数，运行少量示例确认；不兼容时记录原因并评估现有 PEFT 短测脚本。已试验环境继承 Anaconda 包且有 pip 冲突。
- [ ] 从任务 3 的少量合法训练样本做可恢复短试验；使用 Qwen3.5 本地模型及与此前已实测兼容的量化/LoRA 配置作起点，目标模块、参数数量和优化器需记录。
- [ ] `prepare_model_for_kbit_training` 默认 FP32 upcast 曾 OOM；此前手动冻结 FP16 未量化权重的实验只通过 3–5 步，须在真实样本上重新验证有限 loss、非零梯度、数值稳定、参数确实更新；不是默认已证明可靠。
- [ ] 真实前向、反向、优化器更新，记录模型/训练样本实际 token、是否补齐、CUDA allocated/reserved、系统显存、loss、步时；显存不足时记录并按 1.3 缩短上下文或调整批量后重试。
- [ ] 保存 Adapter、tokenizer、参数、模型 revision、系统提示/解析器版本、数据清单 hash、随机种子及训练日志；独立重新加载相同基座与 Adapter，比较固定输入 logits / 输出，报告容差和实际值。

**验收：** 至少一次基于真实且可审查轨迹的完整更新和保存重载；无数据、长度不可行或 OOM 时报告失败原因。低损失不等于任务能力提升。

### 任务 6：微调前后在相同小仓库上比较

- [ ] 使用任务 4 同一框架/工具、仓库初始快照、任务集合、提示、生成参数和步数上限，分别运行原始模型和加载 Adapter 的模型；串行运行避免争抢 4 GiB 显存。
- [ ] 汇总解析成功、工具调用合法/结果处理、最终测试通过率、平均步骤、资源、失败轨迹及各自分母；对非确定性重复记录种子与次数。
- [ ] 根据验证集分析后，锁定方案，在从未参与选择的独立测试任务上比较；保留每个版本的日志及仓库 reset 信息。
- [ ] 如原始与微调都失败、微调退化或样本过少，照实报告；不使用训练轨迹完成率冒充未见任务泛化。

**验收：** 对同一批任务生成原始 vs LoRA 的可复现报告，说明是离线单步、真实闭环还是两者；不宣称官方 SWE-Bench Verified 已评测。

## 五、里程碑与执行顺序

| 里程碑 | 结果 | 失败时的下一步 |
|---|---|---|
| M1：工具配置 | 固定版本的真实框架能解析并执行预设命令 | 排查 Docker、配置或版本；只报配置未就绪 |
