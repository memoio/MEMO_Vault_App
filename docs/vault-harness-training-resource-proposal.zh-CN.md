# Qwen3.5-0.8B 三条 Harness 最小流程：资源与训练时长方案

评估日期：2026-11-09。适用范围：使用现有选定数据集，依次完成 SWE-Agent、OpenHands、AgentLab / BrowserGym 三条路径的最小训练与评测闭环。三路共用 Qwen3.5-0.8B 基座，分别训练和保存 Adapter；不要求部署 EverOS 前后端。

## 一、申请资源

| 项目 | 建议申请 | 说明 |
|---|---|---|
| GPU | **1 张 24 GB 显存 NVIDIA GPU**，例如 RTX 3090 或同级 | 三条路径顺序运行，不需要三张 GPU；训练采用 4-bit QLoRA。 |
| CPU | **至少 8 物理核 / 16 逻辑线程** | 用于数据处理、训练环境、容器及浏览器。 |
| 内存 | **64 GB RAM** | 为数据转换和框架评测保留空间。 |
| 存储 | **200 GB 可用 SSD 或 NVMe** | 可用空间用于模型、数据、环境、Docker 镜像、日志和检查点；不是磁盘总容量。 |
| 机器使用窗口 | **2～3 个工作日** | 规划值，覆盖环境准备、数据检查、训练及基础评测；不保证开发或排障一定在此时间内完成。 |

24 GB 是为当前目标提出的建议申请配置，**不是已实测证明的最低显存**。16 GB 可作为更紧张的备选，但还没有在真实数据上验证；现有 8 GB 在当前软件配置下对 1,024 token 的合成样本前向已出现显存不足。数据处理、镜像大小和评测环境不同会改变 CPU、内存和磁盘需求。

## 二、最小实现范围

三条路径分别使用 SWE-smith、AgentInstruct / CodeAct、Mind2Web 中已选的候选数据，保持原训练、验证和测试任务隔离。每条路径从训练候选中选择 **20～50 条已审计轨迹**，经各自框架动作格式和 Qwen3.5 模板转换，保留来源、原划分、排除原因和截断报告。训练时先按**每路约 1,000 个有效决策样本**估算；实际数量以转换报告为准。验证和测试任务不进入训练。

每路独立完成：

1. 检查框架工具语义和样本的 system、任务、观察、目标动作及 loss 标签；审计并修正或排除不可用样本。
2. 使用统一的 Qwen3.5-0.8B 基座，以 4-bit NF4 QLoRA、FP16、batch size 1、梯度检查点开展短测；先验证 10 个优化器步骤、有限 loss、参数更新、Adapter 保存和重载。
3. 以 2,048 token 为初始目标上限进行真实样本验证，确认显存余量后再尝试 4,096；如失败则降低预算或调整实现。截断或分段必须可配置、可追溯，并保留任务、必要工具定义、目标动作和必要反馈；不能通过目标答案反向裁剪网页。
4. 在对应的真实框架环境中，用少量独立任务对比基座和该路径 Adapter，记录动作可解析、工具反馈、任务结果和失败原因。SWE-Agent 和 OpenHands 需准备各自的执行环境；AgentLab / BrowserGym 需准备对应浏览器和网页环境。离线 SFT 不需要同时启动这些环境。

该方案的“跑通”是验证数据、训练、保存重载及真实框架交互的工程闭环，不承诺任务成功率、论文结果或所有样本的完整原始历史。各路转换质量、许可证和重复数据仍须按项目计划检查。

## 三、上下文长度与数据约束

单条样本的输入、历史和目标共同占用 token 预算；整个数据集可以逐批读取，无需一次全部装进显存。当前 SWE 已转换训练集共有 4,923 个决策，按目标 tokenizer 和训练模板统计，未截断长度中位数约 13,091 token，最长 130,279 token。预算为 2,048 / 4,096 token 时，分别只有约 7% / 11% 的决策能保留完整历史，其余需要截断或分段。因此，**24 GB 方案以受控处理上下文为前提**，不保证容纳所有原始长轨迹。

现有 SWE 的 1,024 token 导出已完成：训练保留 2,026 / 4,923 个决策、验证保留 190 / 442，所有保留样本均发生截断。该导出不代表 2,048 token 的最终样本数；OpenHands 和 AgentLab 转换成最终框架格式后也须重新统计。AgentLab 应先将原始网页转换为适用的网页观察及元素映射，不能将原始 HTML 长度直接当作最终输入长度。

## 四、训练时间与机器使用时间

当前没有 24 GB GPU 上三条路径的真实训练测速，以下是**规划情景，不是实测预测**。假设每路 1,000 个有效决策、2 个 epoch、batch 1、梯度累积 1、不丢弃样本，则每路约 2,000 个优化器步骤，三路共约 6,000 步：

| 假设平均速度 | 每路纯训练循环 | 三路合计纯训练循环 |
|---:|---:|---:|
| 1 秒 / 步 | 约 33 分钟 | 约 1 小时 40 分钟 |
| 3 秒 / 步 | 约 1 小时 40 分钟 | 约 5 小时 |
| 5 秒 / 步 | 约 2 小时 47 分钟 | 约 8 小时 20 分钟 |

因此建议将**纯训练循环按三路合计约 2～9 小时预留**。上述 1～5 秒/步只是用于申请资源的假设区间，不保证实际速度落在其中；样本长度、GPU 型号、实现和梯度累积均会改变结果。模型加载、数据转换与 tokenization、验证、检查点保存、镜像下载、框架评测和排障时间均未包含在表中，所以总体建议申请 **2～3 个工作日机器使用窗口**。如果框架接口尚需开发、环境安装失败或多轮排障，可能超过该窗口。

拿到机器后，以各路径真实长度分布运行 50～100 个优化器步骤，记录训练循环平均秒/步、GPU 峰值以及加载、验证、保存耗时。按 `实际有效样本数 × epoch ÷ 有效 batch size` 估计步数，并以训练器实际处理末尾 batch 的行为修正；再乘同配置实测秒/步，加上其他阶段实测耗时。10 步短测仅验证兼容性，不作为稳定速度。

## 五、评估依据与执行关口

2026-11-09 在 RTX 2060 SUPER 8 GB 上，使用完整 Qwen3.5-0.8B、LLaMA-Factory 0.9.5 加载的 NF4 QLoRA 配置：无 padding 的 768 token 合成样本完成一次参数更新，PyTorch 峰值 allocated 约 7,190 MiB；896 和 1,024 token 前向均出现 OOM。512 token 首次出现非有限梯度，动态 loss scaling 降低 scale 后第二次更新成功。这些只是合成单步探针，尚不能替代真实训练、保存重载或多步吞吐测试。

按本方案拿到资源后，先确认磁盘、驱动及框架依赖，再完成 SWE 真实数据 10 步和保存重载；依照实测调整 token 预算与估算时间。SWE 路径跑通后，按相同验收方式依次完成 OpenHands 和 AgentLab。三路使用同一基座、各自独立 Adapter，框架评测使用固定版本、任务和生成参数，比较基座与 Adapter。

完整硬件检查、原始长度分布、显存探针条件及数据报告位置见 [三条 Harness 训练资源评估](vault-harness-training-resource-assessment.zh-CN.md)。
