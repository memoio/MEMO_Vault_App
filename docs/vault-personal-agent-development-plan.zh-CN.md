# MEMO Vault 个人 Agent：基于开源模型的 Harness 微调计划

> **2026-11-09 模型决策更新：**后续三条独立 Harness 路径统一以 `Qwen/Qwen3.5-0.8B`（本机 revision `2fc06364715b967f1860aea9cf38778875588b17`）为共同基座。下文第二节和其他位置涉及的旧模型选择及相应 P0 步骤已过时，不再作为执行依据；数据分组、接口核验、独立 Adapter 和评测原则继续有效。新的数据审计和资源结果见 [Harness 数据状态](vault-harness-data-status.zh-CN.md)。

更新：2026-11-06。本文是 Vault 下一步原型开发计划，不代表训练、框架集成或评测已经完成。本次战略调整：**不再把训练通用 Agent 作为前置阶段**；选择已经预训练和指令微调的开源模型，针对 OpenHands、SWE-Agent、AgentLab 的具体工具接口分别准备数据、微调和评测。个人授权轨迹与 Vault 记忆仍作为后续阶段。

相关资料：[ADP 导出与开发现状](vault-adp-development-proposal.zh-CN.md)、[旧模型的本机资源试验](vault-adp-training-resource-plan.zh-CN.md)、[现有候选数据审计](vault-stage1-data-audit.zh-CN.md)、[接口核查](vault-stage1-tool-interface-review.zh-CN.md)、[旧 Qwen 样本试制](vault-stage1-qwen-candidates.zh-CN.md)。历史文档中的通用 Agent 路线和旧模型资源数据仅作历史记录，以本文为当前计划。

## 一、目标和整体路径

```text
开源预训练并完成指令微调的 Qwen Coder 模型 B0（保留只读）
   ├─ OpenHands 选定版本与工具 + 匹配轨迹 → 独立 D_tool LoRA
   ├─ SWE-Agent 选定版本与工具 + 匹配轨迹 → 独立 D_swe LoRA
   └─ AgentLab / BrowserGym 选定版本与动作 + 匹配轨迹 → 独立 D_web LoRA
                                  ↓
         用户选择一个已验证的 Harness / 领域 Agent
         + 用户授权且经审核的个人轨迹 → 可选 P_user LoRA
         + Vault 中该用户授权范围内的记忆 / RAG
                                  ↓
         用户个人 Agent：模型决定动作，运行框架执行工具并返回结果
```

三个领域 LoRA **分别从相同 B0 独立训练**，不串联，也不依赖 General Agent。先打通一条，再扩展到另外两条；每条路径都有固定数据、工具版本、输出格式、运行循环和独立评测。这里训练的是模型参数，Harness 提供动作解析、环境和执行机制，不因微调而自动改变框架代码。工具执行与训练可以分开：离线监督微调使用轨迹中已有反馈；真实闭环评测时才实际执行工具。

阶段目标是验证小模型的格式适配与简单任务能力，不承诺解决真实 SWE-Bench Verified、WebArena 或达到论文中的大模型成绩。

## 二、模型选择：先试 Qwen2.5-Coder-1.5B-Instruct

### 2.1 首选与备选

| 用途 | 模型 | 选择理由和边界 |
|---|---|---|
| **首选试验** | [Qwen/Qwen2.5-Coder-1.5B-Instruct](https://huggingface.co/Qwen/Qwen2.5-Coder-1.5B-Instruct) | 官方代码专用、完成预训练及指令后训练的 1.54B 开放权重模型；Apache-2.0。与论文 Coder 系列一致，1.5B 是性能与显存的候选折中，**本机微调尚未验证**。 |
| **显存备选** | [Qwen/Qwen2.5-Coder-0.5B-Instruct](https://huggingface.co/Qwen/Qwen2.5-Coder-0.5B-Instruct) | 同系列更小，可在 1.5B 经合理优化仍无法训练或运行时测试；它也没有在本机实测，不能将非 Coder 0.5B 的实测直接移植。 |
| **已有对照** | [Qwen/Qwen2.5-0.5B-Instruct](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct) | 本机已缓存并做过合成数据 LoRA 预实验；可用于回归或资源比较，不是本次首选。 |

两个 Coder 模型都已进行指令后训练，但官方模型卡不等于已经在本项目三种 Harness / 论文四类数据上训练完成，也不保证可以按所选接口稳定调用工具。模型与数据各自许可证及适用范围仍需核验；模型下载前确定固定 revision，保存权重、tokenizer、配置及哈希。

### 2.2 为什么选 Coder，论文实际证明了什么

[ADP 论文第 5–6 节和表 3–5](https://arxiv.org/pdf/2510.24702)在主要框架实验中使用 Qwen2.5-Coder-Instruct 系列及 LLaMA-Factory 的 SFT 流程，展示的是 **7B、14B、32B** 等模型在指定数据混合和评测下的表现；也存在其他模型和任务设置。它**没有提供本计划的 1.5B / 0.5B 模型在四份选定数据与三个框架上微调后的成绩**，不能把论文数值归给这些小模型，也不能仅凭论文断定 Coder 在网页或所有工具任务上优于普通 Instruct。

作为代码能力的间接参考，[Qwen2.5-Coder 官方技术报告表 16](https://arxiv.org/pdf/2409.12186)报告：HumanEval 上 1.5B-Instruct 为 70.7，0.5B-Instruct 为 61.6；这是代码基准、对应报告设定下的模型成绩，不是 Agent 工具调用、多步任务或 Vault 的成绩，也不是在论文 ADP 数据上微调的结果。1.5B 的更大参数规模和这些代码评测支持其作为优先尝试，并不保证在我们的具体数据、量化及 4 GiB 条件下更好。

因此，当前结论是：**1.5B Coder 是待实测的首选候选，而非已证实既能在本机训练、又在论文 Agent 数据集上表现最好的模型。** 网页、工具调用、中文及记忆任务都需在相同环境中实测；有需要时将已有普通 0.5B 作为对照。

## 三、本机资源与验证关口

本机 GPU 为 NVIDIA GeForce RTX 3050 Laptop，显存总量 4,096 MiB；2026-11-06 检查时空闲约 2,577 MiB，空闲量会随桌面/其他进程变化。1.54B 权重若按 FP16 粗算约 2.87 GiB，仅是 `1.54e9 × 2 bytes` 的权重理论体积，尚未包含计算缓冲、激活、LoRA、优化器、框架与 CUDA 开销，且已超过当时的空闲显存。**推理能装下不等于 LoRA 微调能装下**。

现有实测是普通 Qwen2.5-0.5B-Instruct：LoRA r=8、batch 1、512 补齐、8 条约 54 token 的合成数据，100 步约 24.14 秒，峰值 allocated 2,077 MiB / reserved 2,712 MiB。不能用于预测新模型或真实长轨迹速度和显存；取消原先对通用阶段及新路线的固定分钟数估算。

### 3.1 执行顺序和退路

1. 下载前核验模型卡与许可、剩余磁盘，固定精确 revision / hash；使用独立环境，不覆盖现有模型和项目依赖。
2. 在训练时重新记录空闲 GPU 显存、CPU 内存、磁盘、驱动、CUDA、PyTorch、Transformers、PEFT、量化库版本及兼容性。**先试量化推理与 1.5B QLoRA**：4-bit 加载冻结基础权重，LoRA 更新少量参数；batch=1，短序列 128/256 起步、gradient checkpointing，逐步测试 512 及真实样本长度。NF4、double quant、优化器精度等以硬件/库支持和实测为准。
3. 真实完成 forward、backward、optimizer step、保存/重载和一次推理；记录 alloc/reserved/系统峰值、耗时及失败/OOM。一次短测仅证明当前输入配置可行，不能推断更长上下文可行。
4. 若 1.5B 在可接受的短序列和内存配置下仍 OOM 或不可用，先排查兼容性和资源占用，不终止用户进程；再切换 0.5B Coder 并重复同样测试。仍不满足则使用已有 0.5B 对照完成流程验证，或明确需要更大显存；不能把任意方案称为已适配 4 GB。
5. 先对训练候选使用目标 tokenizer 重新计算实际模板长度。当前旧模型实验 982 条候选中大量超过 512 token，不能直接换模型复用其 `input_ids`、labels 和 tokenizer；必须重建目标模板并测长。

量化 base 上训练出的 LoRA 保存父模型 revision、量化参数及依赖。后续若生成完整合并快照，需在可用的未量化父模型和兼容 PEFT 版本上单独验证 dtype、CPU 内存、磁盘和合并前后输出；不得假设 4-bit 基座可以无损合并或使用多个 Adapter 即自动叠加。失败则保留 B0 与对应 LoRA，作为可加载的独立产物，个人多层方案需另行验证。参考 [PEFT 文档](https://huggingface.co/docs/peft/main/developer_guides/checkpoint) 和 [QLoRA 论文](https://arxiv.org/abs/2305.14314)。

## 四、现有数据与复用边界

### 4.1 四个公开来源

| 来源 | 官方入口 | 初期作用与主要限制 |
|---|---|---|
| AgentInstruct | [数据](https://huggingface.co/datasets/zai-org/AgentInstruct) | OS/工具轨迹；示范及源 loss 标记要正确保留。 |
| CodeActInstruct | [code-act 数据](https://huggingface.co/datasets/xingyaoww/code-act) | Python 交互；选择 codeact 子集，原始 `<execute>` 协议不自动等于目标 Harness 工具。 |
| SWE-smith trajectories | [数据](https://huggingface.co/datasets/SWE-bench/SWE-smith-trajectories) | 合成仓库修复轨迹，不等同真实 SWE-Bench Verified；源工具声明版本、参数及执行语义需核实。 |
| Mind2Web | [数据](https://huggingface.co/datasets/osunlp/Mind2Web)、[项目](https://github.com/OSU-NLP-Group/Mind2Web) | 网页任务与快照；`backend_node_id` 不等于 BrowserGym 的元素标识，网页可能无法重放，长 HTML 和目标泄漏要处理。 |

每份数据及其来源、许可和派生用途单独核对；不要随意下载完整大数据集。ADP 标准化只是中间表示，不是特定 Harness 的训练输入，也不提供可执行环境。保留原始文件、revision、hash、选择清单、排除原因与转换报告。

### 4.2 已有本机成果

- `.memo-vault/agent-training/datasets/paper_adp_v2/`：四来源已选 897 条的五类型 ADP 候选。按现有划分：train/general 466、train/domain 283、validation 76、test 72。**这些名称是旧通用路线留下的数据划分标签，不代表必须继续训练通用模型。**
- 之前生成 982 条 AgentInstruct / CodeAct Qwen 决策样本，属于旧普通 0.5B tokenizer、原始混合工具协议和待审核候选；不能不加检查地作为新模型及 Harness 训练集。
- SWE 100 条 general 候选原始重建一致，2,164 个动作通过有限结构检查；Mind2Web 92 条 general 候选的 610 个目标 ID 在相应 HTML 中唯一出现。这些是审计，不证明工具版本一致、浏览器映射成功或可训练。
- `src/everos/agent_training/` 中下载、ADP 转换与审计脚本可继续复用；保留历史数据和报告，不自动覆盖。

### 4.3 新的任务组与划分策略

以源记录中已固定的分组、split、来源版本为依据，**不重新打乱或将验证/测试搬入训练**；按目标领域重新创建训练 manifest。旧 `train/general` 与 `train/domain` 理论上都可作为领域训练候选，但必须先统一检查原 split、source group、exact/near duplicate、领域适用性和历史 few-shot 污染，且每一原始任务只归于一个训练/验证/测试划分；领域之间可共享训练轨迹但须显式记录，防止评测泄漏。已存验证集用于选型、调参，测试集只在方案确定后进行最终评价。不同领域需要各自的验证、测试及任务；数量不足就报告不足，不复制凑数。既有数据的语义近重复及跨来源重复尚未排除。

旧计划的 500 / 300 是历史建议上限，不代表已筛选完成的训练数量；新路线按每个 Harness 的有效轨迹和决策数分别报告，明确“轨迹”“决策样本”“token”“训练步数”的区别。优先用小批样本验证整条流程，效果和许可核查通过后再扩大。

## 五、三条独立 Harness 路径

| 路径 | 目标框架 / 环境 | 起点数据 | 本地第一批评测 |
|---|---|---|---|
| A：编程和工具 | OpenHands 固定版本与工具配置 | AgentInstruct、CodeAct；需核实与所选工具的对应 | 受控临时目录中的读取、命令、结果处理和简短编码任务 |
| B：仓库修复 | SWE-Agent 固定版本和工具配置 | SWE-smith；验证源工具与目标工具的语义 | 可复现的小仓库、已知缺陷与测试 |
| C：网页任务 | AgentLab + BrowserGym 固定版本和动作空间 | Mind2Web；验证快照元素 ID 与目标环境的对应 | 本地可复现网页中的查看、点击和输入 |

三框架能提供或配合工具执行，但不会直接把公开数据变成合法训练输入，也不等于 SFT/LoRA 训练器。框架代码、模型服务接口及工具名称和行为以实际固定版本为准；不要把现有 mock 运行配置宣称为官方框架集成。框架版本与论文时代可能不同，需要明确差异。用户请求的真实环境在资源不足时可分步集成，记录未完成项。

## 六、执行任务：先跑通一条，再扩展三条

| 顺序 | 任务 | 产物 / 完成标准 |
|---|---|---|
| P0 | 基座模型与本机兼容 | 固定首选 revision、验证量化/训练依赖；1.5B QLoRA 真实正反向和保存重载报告；失败按第三节执行备选，不伪称成功。 |
| P1 | 选首个 Harness，固定真实接口 | 记录框架版本、工具声明、参数、解析与结果格式、任务环境、模型接入方式及许可证；选择受限本地任务。先选能部署且数据映射最明确的一条。 |
| P2 | 数据划分、匹配和审计 | 依据既有 split 生成训练/验证/测试 manifest；逐动作记录来源及工具映射证据、长上下文处理和排除原因；解决明确的泄漏风险。 |
| P3 | 构造目标模型与 Harness 训练样本 | 使用目标 tokenizer 和聊天模板；保留系统信息、工具、任务、历史动作及反馈；助手目标单独 mask，校验每个动作的参数、历史与来源，不编造工具结果。 |
| P4 | 建立原始模型基线 | 在相同固定的验证任务上记录动作可解析率、工具选择/参数、闭环任务成功率、失败案例及资源，区分离线与在线。 |
| P5 | 短试运行和正式领域 LoRA | 先小步验证 loss、峰值内存、保存/重载；再按显存实测决定长度、步数、累积和训练配置，记录基座、版本、manifest、随机种子、日志及成本。 |
| P6 | 加载并对比评测 | 同一 Harness、工具、任务与指标比较 B0 vs B0+D；固定验证集调参，保留最终测试集；测普通对话回归，报告样本数与失败案例。 |
| P7 | 扩展其余两条路径 | 按 P1–P6 分别执行；三个 Adapter 均从同一个 B0 出发，分别评估、保存，不把一条路径结果代表三条。 |
| P8 | 用户个人适配、记忆与接口 | 用户授权、数据隔离和适配充分验证后再做个人 Adapter；先实现本地运行及调用，再接前端。 |

P0 和 P1 可独立调研；前期预计优先 OpenHands 或 SWE-Agent 中**可本机部署、数据映射证据更充分**的一条，以实际环境测试确定。不要在尚未固定 Harness 时就把既有候选当作对应训练数据。小规模构造的验证样例与最终测试任务需按源任务隔离；不同框架输入/输出和执行环境不可直接混用。

### 6.1 训练与评测规则

- 基座、Adapter、tokenizer、聊天模板和工具接口各自版本化。Adapter 不是独立基础模型，必须搭配正确父模型及运行配置。
- 长轨迹按有充分上下文的决策点拆分；保留任务、相关工具声明、必要历史与反馈。禁止用真实正确目标反向裁剪网页作为输入造成答案泄漏。无法保留充分上下文或无法证明工具映射的样本暂缓并说明。
- 离线指标包括解析、动作选择和参数合法；真实闭环在受控工具环境检查最终任务成功、步骤数、错误恢复。不要把离线回放冒充真实执行。
- 三条都需要各自的领域指标和基本对话回归。报告预测及人工/任务评测不确定性，不能将论文结果归因于 ADP 格式本身。

## 七、用户个人 Adapter 与 Vault Memory

在用户选择已验证的领域模型/框架之后，用户可单独授权导入轨迹用于训练：

1. 复用当前 Vault 对所支持的 DeepSeek Harness v4、Claude 归档的 ADP / ATIF 子集导出，不能把导出结果直接视为训练格式；核查用户消息、工具声明、动作、返回和授权。
2. 按所选 Harness 逐项验证源轨迹是否能映射，检查敏感信息、样本质量、工具权限及任务划分；人工审核小批试验数据。数据不足或无法安全映射时跳过训练，可仅使用已授权记忆检索。
3. 每个用户单独绑定父模型、领域 LoRA、数据版本、训练用途、授权和个人 Adapter；同一用户撤销授权后应阻止加载并执行删除策略。记忆检索授权与训练授权分别处理。
4. 物理装载优先研究 `领域父模型快照 + 用户 Adapter`：量化合并/重载和个人 Adapter 训练可行后才能启用。若无法合并，就保留领域 LoRA 并明确暂不可训练个人第二层，或单独验证受支持的多 Adapter 方案；不能假设任意 LoRA 可叠加。
5. 比较领域父模型与个人适配后在相同用户独立任务上的效果和普通能力回归，保存来源与指标。每位用户隔离，不把个人数据混进共享基座。

Vault 现有 `adp_export.py` / `adp_converter.py` 为支持范围内的用户会话提供 ADP / ATIF 子集，现有记忆入口可评估复用；这些不代表训练服务、用户隔离或新 Agent 运行链路已经集成。

## 八、运行时、接口与前端后续计划

先以命令行或本地 API 验证，选择固定的 `tool` / `swe` / `web` 配置、对应模型和工具；运行时处理用户身份、授权、记忆检索、工具解析、最大步骤、超时和错误反馈。执行仓库任务使用隔离的临时环境，网页使用本地受控任务；外网暴露、生产安全边界和正式框架服务需另行设计验证。

后续把三个通过验证的领域 MEMO Vault Agent 接入现有前端，并支持：

1. 查看和选择具体 Agent / Harness，展示可用能力和状态。
2. 选择已导入轨迹并分别授权个人训练与记忆使用，展示授权范围和状态。
3. 发起个人适配并查看数据处理、训练或跳过原因；未启用个人 LoRA 时可按授权使用记忆。
4. Agent 准备就绪后，展示 Agent 标识、调用地址、调用方式及必要认证信息；接口设计沿用现有鉴权并执行用户隔离。
